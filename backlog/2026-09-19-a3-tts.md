## Objective

Make Polaris speak: expose a `speak(text)` command so the assistant can read a
short confirmation or answer aloud. **Fish Audio** (`s2.1-pro-free`) is the
primary provider; because the free tier is time-limited and has **no SLA**, an
empty/invalid key or any network failure must fall back to **local macOS speech**
rather than failing the demo. Every utterance must use the **same voice**, which
for Fish Audio means sending the configured `reference_id` on every request.

## Completed

1. **A `Speaker` seam, mirroring A1.** New `app/src-tauri/src/tts/`:
   `tts::Speaker` is a one-method trait (`speak(&str) -> Result<(), TtsError>`
   plus a `name()` logging aid), with `fish.rs` (cloud) and `local.rs`
   (on-device) behind it and `build_backend()` selecting between them. This is
   the same shape as `stt::Transcriber`; only the direction is inverted.
2. **Fish Audio backend.** `POST https://api.fish.audio/v1/tts` with
   `Authorization: Bearer $FISH_AUDIO_API_KEY`, header `model: s2.1-pro-free`,
   and JSON body `{text, reference_id, format, latency}`. The body is built by
   serde from a small struct via the pure `fish::request_body`, and a unit test
   pins that `reference_id` is present in the serialised bytes. The key only ever
   appears in the `Authorization` header; it is never logged, written or included
   in an error.
3. **One fixed voice — enforced.** `POLARIS_TTS_REFERENCE_ID` is **required** for
   the Fish backend. If it is missing or blank, `FishSpeaker::missing_config()`
   reports it before any request is made; `build_backend()` logs the reason and
   constructs the local backend instead of sending a voice-drifting request. The
   check runs **before** the key check, because a request without the voice id is
   exactly what the owner forbids.
4. **Mandatory local fallback.** `FallbackSpeaker` wraps the Fish primary and the
   local `say` backend and falls back on **any** primary failure (missing key,
   network, HTTP, malformed audio) — deliberately broader than A1's narrow
   `Unavailable`-only fallback, because the A3 requirement is that the assistant
   is never silent. Each fallback prints why and notes that this utterance uses a
   different voice. A local-only build is used when Fish config is absent.
5. **Selection.** `POLARIS_TTS_BACKEND` (`fish` | `local`, case-insensitive),
   default `fish`; an unknown value resolves to `fish` **and** reports
   "unrecognized" so the caller warns (`tts::parse_backend`, unit-tested).
6. **Playback.** Fish returns audio bytes (MP3 by default). The simplest approach
   that actually plays them from Rust is used: write to a unique temp file under
   the OS temp dir and hand it to macOS's built-in `afplay`, which supports MP3
   and WAV natively. No new dependency. The local backend needs no separate
   playback step: `say` synthesizes and plays in one call.
7. **Command + events + latency.** `commands::speak` returns a typed
   `SpeechOutcome {backend, latencyMs, characters}` on success and
   `SpeechFailure {label, detail}` on failure. Success prints
   `polaris: tts in <ms> ms via <backend> (<n> chars)`; failure prints the full
   detail to the terminal and emits the **existing** `error` event with a short
   `TTS: <label>` message. No new `PolarisEvent` variant was added: adding one
   would require editing the TS seam (`interfaces/src`, `app/src/lib`), which is
   worker A2's scope. Playback runs on Tauri's blocking pool
   (`spawn_blocking`), never the main thread.
8. **Turkish and English.** Text is passed through unchanged and serialised with
   serde; a test covers a Turkish string with punctuation.

## Fish Audio API facts confirmed before writing the client

Read from <https://docs.fish.audio/api-reference/endpoint/openapi-v1/text-to-speech>
and <https://docs.fish.audio/llms.txt> while implementing:

- Endpoint `POST https://api.fish.audio/v1/tts`, auth `Authorization: Bearer <token>`.
- `model` is a **header** (not body): `s1`, `s2-pro`, `s2.1-pro`,
  `s2.1-pro-free`, `drama-3-preview`; omitted/unknown falls back to `s2.1-pro`.
  `s2.1-pro-free` is the free developer tier.
- Body is `application/json` (or `application/msgpack`); `text` is required.
  `reference_id` (string) selects the **voice**; the docs' own single-speaker
  cURL sample includes `"format": "mp3"` and `"latency": "normal"`.
- `format` is `wav` | `pcm` | `mp3` | `opus`; MP3 defaults to 128 kbps, 44.1 kHz,
  mono. Response is the raw audio (`audio/mpeg` for mp3).

## A3b follow-up — the LIVE Fish path, actually run (2026-09-19)

The premise "the key is absent" was stale: the worktree `.env` holds a real,
non-empty `FISH_AUDIO_API_KEY` and `POLARIS_TTS_REFERENCE_ID`. A new `#[ignore]`d
test, `tts::tests::manual_live_fish_synthesises_mpeg_and_speaks`, exercises the
real backend end to end: it builds `FishSpeaker::from_env()`, asserts
`missing_config() == None`, calls `FishSpeaker::synthesize()` and asserts the
returned bytes are **non-empty and MPEG** (ID3v2 tag or `0xFF Ex` frame sync),
then drives the exact production `speak_and_log()` path (temp file -> `afplay` ->
`polaris: tts in <ms> ms via fish`).

`src/tts/fish.rs` was split for this: the HTTP step now lives in
`synthesize`/`synthesize_with_key` (returning `Vec<u8>`) and playback in `play`,
with `Speaker::speak` composing the two. Behaviour is unchanged; the existing
"missing key / missing voice id fails before any I/O" tests still pass.

Exact command actually run (from `app/src-tauri`; the test also self-loads `.env`):

```
$ set -a; . ../../.env; set +a; caffeinate -i cargo test manual_live_fish -- --ignored --nocapture

test tts::tests::manual_live_fish_synthesises_mpeg_and_speaks ... ok

test result: ok. 1 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 10.92s
```

The first run of the same test measured **7389 ms via fish**; the re-run above
measured **6668 ms** — both for the same 42-character Turkish/English sentence
(`Merhaba, this is Polaris. Onaylıyor musun?`). The live Fish synthesis +
playback latency is therefore **~6.7-7.4 s**, dominated by the provider
round-trip plus `afplay`; the local `say` path measured ~4.7 s for a comparable
sentence. Audio genuinely played through `afplay` (the test errors otherwise),
and the latency line is the production line printed by `speak_and_log`, not by
the test.

The task's suggested `cargo test -- --ignored --nocapture` (no filter) was **not**
used as-is: the two ignored tests both mutate the process environment
(`manual_local_fallback_...` sets `FISH_AUDIO_API_KEY=""`), and the default
multi-threaded harness would race our `FishSpeaker::from_env()` against that
write. The live test was run filtered by name (above) so the result is
deterministic. No production behaviour was changed because of this.

**TypeScript:** not run. No file under `app/src/**` or `interfaces/**` was
changed, so there is nothing for `npm run typecheck` / `npm run build` to cover on
this branch (and A2 owns those files).
