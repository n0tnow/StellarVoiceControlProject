- **Date:** 2026-09-19
- **Worker/Agent:** opencode worker (deepseek-v4.1-flash)
- **Branch/Worktree:** `feat/a1-stt` / `.worktrees/a1` (based on `feat/a0-push-to-talk-notch`)
- **PR:** none (per the task: push only, no PR, no merge, no tag)

## Objective

Turn the A0 WAV into a transcript: capture `ready` → transcribe automatically →
emit `transcript { text, final: true }` on the `polaris-event` stream, print it to
the Rust terminal, and show only "Thinking" in the notch while it runs.

## Completed

1. **Trigger.** A finished capture is handed to a dedicated STT worker from the
   capture thread itself (`capture.rs`), so *every* path that produces a WAV —
   hotkey or `capture_stop` command — triggers transcription the same way. The
   hotkey driver and the Tauri main thread never do STT work.
2. **States.** `CaptureState` gains `transcribing`. The overlay shows "Thinking"
   from that state alone and returns to the resting pill when the transcript (or
   the failure) lands. The result reuses the existing
   `transcript { text, final }` variant; no new event variant was needed.
3. **Backend abstraction.** `stt::Transcriber` is a one-method trait
   (`transcribe(&Path) -> Result<Transcription, SttError>`). `GroqTranscriber` is
   the only implementation today; `WhisperCpp` can be dropped in by implementing
   the trait and constructing it in `lib.rs`. No call site changes.
4. **The API key.** Read from the process environment, with an optional
   gitignored `.env` (walked up from the working directory) that never overrides
   a real environment variable. The key is only ever placed in the request's
   `Authorization` header; it is never logged, never written to a file, never
   part of an error, and no code path searches the machine for it. Missing key:
   capture still works, the overlay shows **"No STT key"**, and the terminal
   explains what to set.
5. **Language.** Auto-detect (no `language` parameter) by default.
6. **Latency.** Measured from capture completion to the transcript event and
   printed as `polaris: transcript in <ms> ms (audio <ms> ms): <text>`.
7. **Retention (A0 review MAJOR-3).** A recording is deleted only after a
   *successful* transcription. Failed recordings are kept — they are the only
   copy. The recordings directory is capped at `MAX_RECORDINGS = 10`; the newest
   wins, so a just-failed file always survives.
8. **Failure modes.** Silent/empty, under 300 ms, missing key, network/timeout,
   provider HTTP error, malformed response — each maps to a short overlay label
   and a full terminal line. Nothing panics; nothing wedges; the next hold works
   because `start` only short-circuits while `Recording`.

## Groq schema — what I confirmed before writing the client

Read from <https://console.groq.com/docs/speech-to-text> while implementing:

- Endpoint `POST https://api.groq.com/openai/v1/audio/transcriptions`
  (OpenAI-compatible multipart form upload).
- `file` (the audio bytes; `wav` is supported), `model` (**required**),
  `language` (optional ISO-639-1), `prompt` (optional), `temperature`
  (default `0`), `response_format` (default `json`). `json` returns
  `{"text": "..."}`; `verbose_json` adds timestamps/metadata.
- The task's provider facts held: `whisper-large-v3-turbo` is the multilingual
  model (`$0.04`/hour, ~216× realtime), and the free-tier limits quoted
  (25 MB file cap, minimum billed length 10 s) match the page.

The request is built as a hand-rolled multipart body so its exact bytes are
unit-tested, and the `json` response is parsed from a recorded sample payload.

## Language decision: auto-detect, not a forced `tr`

The docs say an explicit `language` «will improve accuracy and latency», which is
a real argument for passing `tr`. I still chose **auto-detect by default**:

- Commands are *code-switched*. The user is Turkish but the commands mix an
  English vocabulary that must stay English (`send 10 USDC to ada`, `swap`,
  `USDC`). Forcing `tr` makes Whisper render those English tokens as Turkish
  phonetics, which would corrupt exactly the entities the chain parser needs.
- Auto-detect costs one decoder step, and on `whisper-large-v3-turbo` a 3 s clip
  is milliseconds on Groq's hardware — the 2 s budget is network, not inference,
  so the latency argument is weak here.

This is a default, not a lock-in: `POLARIS_STT_LANGUAGE=tr` forces Turkish for a
user who only ever speaks Turkish. The doc comment records the trade-off.

## Notes for review

- `reqwest` is added with `default-features = false, features = ["blocking",
  "native-tls"]`: blocking keeps the call off the async runtime, and native-tls
  uses the macOS system trust store instead of a bundled crypto stack.
- `Capture` is now `Clone` (it already wrapped `Arc<Shared>`); the STT worker
  holds a clone to drive `transcribing`/`idle`/`error` transitions, and the
  hotkey driver keeps using the managed instance. No A0 behavior changed.
- `CaptureStatus` gained a `label` field. It is `None` for A0 microphone errors
  (the UI keeps "Mic error") and carries the short A1 copy for STT failures.
- A0 `expanded_size`, ear layout, three-column grid, and centre column are
  untouched. The only CSS addition is a slower pulse for `transcribing`.
