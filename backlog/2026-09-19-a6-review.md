## Executive Summary

Step A6 introduces a typed input path as an alternative to push-to-talk: double-tapping the `Control` key toggles a focusable, notch-anchored Tauri window (`prompt`) with a textarea, which executes intents against the existing `@polaris/agent` pipeline and speaks results via `@polaris/speech` when an on-screen toggle is active.

The architectural separation between the pure double-tap detector (`ctrl_tap.rs`), the non-invasive `hotkey_flags` fan-out, and the distinct Tauri entrypoint (`prompt.html` / `main.tsx`) is well conceived. Furthermore, XSS sanitization, `localStorage` fallbacks, and non-test error propagation avoid `unwrap`/`expect` hazards.

However, the change cannot be approved in its current state due to one **BLOCKER**, several **MAJOR** correctness and thread-safety defects, and tautological unit tests:
1. **Broken UI Animation (BLOCKER):** `PromptPanel.tsx` toggles the `.is-open` CSS class on open/close, but `prompt.css` never defines any rule for `.is-open` or non-open heights. As a result, the sheet never animates its height during open or close; instead, closing waits 240 ms and abruptly vanishes via `prompt_hide`.
2. **Lock Held Across Callbacks (MAJOR):** `hotkey_flags::notify_sample_observers` invokes registered callbacks while holding a `std::sync::Mutex` lock, risking deadlocks and thread contention during event dispatch.
3. **Unprotected FFI Panic Boundary (MAJOR):** A panic inside an observer callback unwinds across the Objective-C block boundary into AppKit without `catch_unwind`, resulting in undefined behavior / process termination.
4. **Alphanumeric Control Chord False Positives (MAJOR):** Because `NSEventMask::FlagsChanged` only captures modifier keys, rapid text editing/terminal sequences with Control (e.g. double `Ctrl+C`, `Ctrl+A` then `Ctrl+K`) are delivered to `CtrlTap` as bare Control presses, falsely triggering the prompt panel.
5. **Tautological Test (MAJOR):** In `ctrl_tap::tests::a_long_control_hold_is_not_a_tap`, the assertion that a rejected hold does not seed a sequence waits 1.0 second (well past the 400 ms `TAP_GAP`), meaning the test would pass even if the hold had incorrectly seeded a pair.
6. **No Scroll Container for Long Answers (MAJOR):** Native window height is capped at 720 pt, but CSS styles lack `overflow-y: auto`, clipping responses longer than 720 pt.

## Detailed Findings

### 1. Pure Double-Tap State Machine (`app/src-tauri/src/ctrl_tap.rs`)

#### Finding 1.1 — Fast typing and command-line Control shortcuts misfire the double-tap detector
- **Severity:** MAJOR
- **Location:** [`app/src-tauri/src/ctrl_tap.rs:111-181`](file:///Users/fatih/StellarVoiceControlProject/.worktrees/a6-text-prompt/app/src-tauri/src/ctrl_tap.rs#L111-L181) and [`app/src-tauri/src/hotkey_flags.rs:140-146,158-164`](file:///Users/fatih/StellarVoiceControlProject/.worktrees/a6-text-prompt/app/src-tauri/src/hotkey_flags.rs#L140-L146)
- **Scenario:**
  `hotkey_flags.rs` monitors `NSEventMask::FlagsChanged`. Alphanumeric and symbol keys (`KeyDown` / `KeyUp`) do not produce `flagsChanged` events. Consequently, when a developer types common shell or editor commands in rapid succession (for example: double `Ctrl+C` to terminate a stubborn process, `Ctrl+A` then `Ctrl+K` in Bash/Zsh to clear a line, `Ctrl+B` then `Ctrl+B` in tmux, or `Ctrl+X` `Ctrl+S` in Emacs), each individual Control press/release takes ~80–120 ms with a gap under 400 ms.
  `CtrlTap::on_modifiers` receives only `ctrl: true`, `ctrl: false`, `ctrl: true`, `ctrl: false`. Because no intervening modifier keys (`option`, `command`, `shift`) were pressed, `foreign` is false, and the state machine interprets this as two deliberate bare Control taps, unexpectedly opening the Polaris prompt and stealing keyboard focus away from the terminal.
- **Recommendation:**
  Document this behavioral limitation explicitly in `ctrl_tap.rs` and the architectural report. If alphanumeric chord filtering is required without full keyboard logging permissions, consider tightening `MAX_TAP_HOLD` (e.g. 180–200 ms) or investigating whether local event monitoring can provide key interception when Polaris is focused.

#### Finding 1.2 — Tautological assertion in `a_long_control_hold_is_not_a_tap`
- **Severity:** MAJOR
- **Location:** [`app/src-tauri/src/ctrl_tap.rs:255-259`](file:///Users/fatih/StellarVoiceControlProject/.worktrees/a6-text-prompt/app/src-tauri/src/ctrl_tap.rs#L255-L259)
- **Scenario:**
  In `a_long_control_hold_is_not_a_tap`:
  ```rust
  // The rejected hold must not seed a sequence either.
  assert!(!machine.on_modifiers(ctrl(true), t0 + Duration::from_secs(1)));
  assert!(!machine.on_modifiers(
      ctrl(false),
      t0 + Duration::from_secs(1) + TAP
  ));
  ```
  This assertion attempts to verify that the earlier rejected hold (> 350 ms) did not leave `first_tap_release` populated. However:
  1. The new press is placed at `t0 + 1s`, which is 1000 ms later—far exceeding `TAP_GAP` (400 ms). Even if the long hold *had* erroneously stored a `first_tap_release`, the gap elapsed check (`now.duration_since(release) <= TAP_GAP`) would have expired anyway.
  2. Any fresh first tap on a default machine *always* returns `false` on release.
  Therefore, this test does not prove that a long hold fails to seed a sequence.
- **Recommendation:**
  Test sequence seeding within `TAP_GAP`: send a tap at `release + Duration::from_millis(100)` and assert that it returns `false` (i.e. does not complete a pair with the preceding long hold). Then send a third tap at `release + Duration::from_millis(200)` and verify it returns `true` (proving that the second tap correctly became the new first tap).

### 2. Observer Fan-Out (`app/src-tauri/src/hotkey_flags.rs`)

#### Finding 2.1 — Mutex lock held across observer callback invocations
- **Severity:** MAJOR
- **Location:** [`app/src-tauri/src/hotkey_flags.rs:66-82`](file:///Users/fatih/StellarVoiceControlProject/.worktrees/a6-text-prompt/app/src-tauri/src/hotkey_flags.rs#L66-L82)
- **Scenario:**
  `notify_sample_observers` locks `SAMPLE_OBSERVERS` and iterates through the observer list, calling `observer(sample)` while holding the `MutexGuard`:
  ```rust
  fn notify_sample_observers(sample: ModifierSample) {
      match SAMPLE_OBSERVERS.lock() {
          Ok(observers) => {
              for observer in observers.iter() {
                  observer(sample);
              }
          }
          ...
      }
  }
  ```
  If an observer synchronously registers another observer (e.g. via `add_sample_observer`), a re-entrant deadlock immediately occurs. Furthermore, because `global_block` runs on an AppKit event delivery thread and `local_block` runs on the main thread during event dispatch, any delay or mutex acquisition within an observer holds the lock across threads, stalling modifier dispatch.
- **Recommendation:**
  Do not hold the lock across the callback loop. Store observers behind an `Arc<Vec<SampleObserver>>` (or clone the vector/slice under the lock, release the guard, and then iterate).

---

#### Finding 2.2 — Observer panic unwinds across Objective-C / FFI boundary
- **Severity:** MAJOR
- **Location:** [`app/src-tauri/src/hotkey_flags.rs:66-82,146,163`](file:///Users/fatih/StellarVoiceControlProject/.worktrees/a6-text-prompt/app/src-tauri/src/hotkey_flags.rs#L66-L82)
- **Scenario:**
  `notify_sample_observers` is called inside `global_block` and `local_block` (AppKit `RcBlock` closures). If any registered observer panics:
  1. The panic unwinds through `notify_sample_observers`, poisoning `SAMPLE_OBSERVERS`.
  2. The panic unwinds through the `RcBlock` across the Objective-C runtime boundary into AppKit's event dispatch loop.
  Unwinding across an `extern "C"` / Objective-C boundary is undefined behavior in Rust and results in an immediate runtime abort, crashing the entire macOS application.
- **Recommendation:**
  Wrap the observer execution loop in `std::panic::catch_unwind` so that a faulty observer logs an error rather than tearing down the AppKit event loop and the application.

#### Finding 2.3 — Permanent observer allocation without unregistration mechanism
- **Severity:** NIT
- **Location:** [`app/src-tauri/src/hotkey_flags.rs:49-59`](file:///Users/fatih/StellarVoiceControlProject/.worktrees/a6-text-prompt/app/src-tauri/src/hotkey_flags.rs#L49-L59)
- **Scenario:**
  `add_sample_observer` appends a boxed closure to a process-global static `Vec` and returns `()`. There is no token or unregister function. While acceptable for a static single-call setup in `prompt_window::setup`, any unit tests or reloaded modules would leak observers indefinitely.
- **Recommendation:**
  Document that `add_sample_observer` is process-lifetime only, or return an unregister subscription token.

### 3. Prompt Window Management (`app/src-tauri/src/prompt_window.rs`)

#### Finding 3.1 — Notch-less and external displays show an unrounded black sheet obscuring the macOS menu bar
- **Severity:** MAJOR
- **Location:** [`app/src-tauri/src/prompt_window.rs:712-733`](file:///Users/fatih/StellarVoiceControlProject/.worktrees/a6-text-prompt/app/src-tauri/src/prompt_window.rs#L712-L733) and [`app/src/prompt/prompt.css:1184`](file:///Users/fatih/StellarVoiceControlProject/.worktrees/a6-text-prompt/app/src/prompt/prompt.css#L1184)
- **Scenario:**
  On Mac setups without a hardware notch (Mac mini, Mac Studio, iMac, external monitors, or MacBook in clamshell mode), `screen.safeAreaInsets().top` is `0.0`. The fallback path selects `screens.firstObject()`.
  The window is placed flush with the screen top: `frame.origin.y + frame.size.height - height` at window level `PROMPT_WINDOW_LEVEL = 25` (`NSStatusWindowLevel`), which renders above the macOS menu bar.
  Because `.prompt-sheet` hardcodes `border-radius: 0 0 22px 22px` (square top corners designed to hide behind a physical notch cutout), on a notch-less screen it renders as an opaque `#060608` rectangle directly over the center of the system menu bar with sharp corners at the top bezel.
- **Recommendation:**
  Detect when the host screen has `safeAreaInsets().top == 0.0` (or expose this via geometry). When no notch is present, either offset the window below the menu bar (similar to Spotlight) or apply rounded top corners (`border-radius: 22px`).

#### Finding 3.2 — Asynchronous `run_on_main_thread` races `show` and event emission
- **Severity:** MAJOR
- **Location:** [`app/src-tauri/src/prompt_window.rs:606-624`](file:///Users/fatih/StellarVoiceControlProject/.worktrees/a6-text-prompt/app/src-tauri/src/prompt_window.rs#L606-L624)
- **Scenario:**
  In `show()`:
  ```rust
  app.run_on_main_thread(move || {
      if let Err(error) = place(&handle, height) { ... }
      if let Err(error) = window.show() { ... }
      if let Err(error) = window.set_focus() { ... }
  })
  .map_err(|error| error.to_string())?;
  emit(app, PromptAction::Open);
  ```
  `app.run_on_main_thread` posts the closure to the main run loop asynchronously and returns immediately. `emit(app, PromptAction::Open)` is dispatched before the main thread has placed, shown, or focused the window. If the webview receives `open` before `window.set_focus()` has completed, `requestAnimationFrame(() => textareaRef.current?.focus())` may run while the window is still unfocused or invisible.
- **Recommendation:**
  Dispatch `emit(app, PromptAction::Open)` from inside the `run_on_main_thread` block, immediately after `window.show()` and `window.set_focus()` succeed.

#### Finding 3.3 — Height clamping does not consider screen dimensions
- **Severity:** MINOR
- **Location:** [`app/src-tauri/src/prompt_window.rs:544,637`](file:///Users/fatih/StellarVoiceControlProject/.worktrees/a6-text-prompt/app/src-tauri/src/prompt_window.rs#L544)

While `width` is clamped against `(frame.size.width - 40.0)`, `height` is not clamped against `frame.size.height`. On displays with scaled heights or vertically constrained auxiliary monitors under 720 pt, `frame.origin.y + frame.size.height - height` produces a negative coordinate, pushing the window off-screen at the bottom.

### 4. React Panel & Frontend (`app/src/prompt/*`)

#### Finding 4.1 — Missing `.is-open` CSS rule breaks open/close animations and causes abrupt window hiding
- **Severity:** BLOCKER
- **Location:** [`app/src/prompt/PromptPanel.tsx:1028`](file:///Users/fatih/StellarVoiceControlProject/.worktrees/a6-text-prompt/app/src/prompt/PromptPanel.tsx#L1028) and [`app/src/prompt/prompt.css:1173-1189`](file:///Users/fatih/StellarVoiceControlProject/.worktrees/a6-text-prompt/app/src/prompt/prompt.css#L1173-L1189)
- **Scenario:**
  In `PromptPanel.tsx`:
  ```tsx
  <section
    className={`prompt-sheet ${expanded ? "is-open" : ""}`}
    style={style}
    aria-label="Ask Polaris"
  >
  ```
  In `prompt.css`, `.prompt-sheet` is styled with:
  ```css
  .prompt-sheet {
    ...
    height: var(--sheet-height, 0px);
    transition: height var(--prompt-motion) var(--prompt-ease);
  }
  ```
  There is **no CSS selector for `.is-open` anywhere in `prompt.css`**.
  When `closePanel()` is called:
  1. `setExpanded(false)` is set, removing `is-open` from `className`.
  2. `sheetHeight` remains at its measured value (e.g. 84px or 220px); `--sheet-height` is not reset.
  3. Because `.is-open` does not exist in CSS, `.prompt-sheet` height remains completely static at `--sheet-height`. **No collapse animation occurs.**
  4. After 240 ms (`COLLAPSE_MS`), `setTimeout` calls `invoke("prompt_hide")`. The window suddenly disappears instantly without any visual transition.
  Similarly, upon reopening, because `sheetHeight` already equals the measured height, no 0 -> measured height CSS transition is triggered; the sheet instantly appears at full size.
- **Recommendation:**
  Update `prompt.css` so that closed state collapses height to 0:
  ```css
  .prompt-sheet {
    height: 0px;
    transition: height var(--prompt-motion) var(--prompt-ease);
  }
  .prompt-sheet.is-open {
    height: var(--sheet-height, 0px);
  }
  ```
  Alternatively, toggle `--sheet-height: 0px` when `expanded` is false.

#### Finding 4.2 — Responses taller than `MAX_WINDOW_HEIGHT` are clipped with no scrolling possible
- **Severity:** MAJOR
- **Location:** [`app/src/prompt/prompt.css:1173-1196,1320-1326`](file:///Users/fatih/StellarVoiceControlProject/.worktrees/a6-text-prompt/app/src/prompt/prompt.css#L1173-L1196) and [`app/src-tauri/src/prompt_window.rs:544,637`](file:///Users/fatih/StellarVoiceControlProject/.worktrees/a6-text-prompt/app/src-tauri/src/prompt_window.rs#L544)

  If an agent answer is lengthy (e.g. 1000 pt tall):
  1. `reportHeight` measures `.prompt-inner` and calls `prompt_resize` with 1000.

  ```css

    max-height: calc(720px - 100px);
    overflow-y: auto;
  }
  ```

## Verdict

### **REQUEST CHANGES**

The branch cannot be merged without addressing the following items:
1. **Fix `.is-open` CSS rule in `prompt.css` (BLOCKER):** Implement the open and closed sheet height rules so the panel actually expands and collapses.
2. **Release `SAMPLE_OBSERVERS` mutex before running callbacks in `hotkey_flags.rs` (MAJOR):** Prevent deadlock and thread contention by invoking observers outside the mutex lock.
3. **Wrap observer execution in `catch_unwind` (MAJOR):** Prevent observer panics from terminating the process across the AppKit FFI boundary.
4. **Fix tautological test in `ctrl_tap.rs` (MAJOR):** Test sequence seeding within `TAP_GAP` (< 400 ms) rather than 1.0 s.
5. **Add answer overflow scroll container (MAJOR):** Ensure answers exceeding `MAX_WINDOW_HEIGHT` can be scrolled.
6. **Synchronize `emit(Open)` with main-thread window focus (MAJOR):** Prevent race conditions where the webview animates before the native window is placed.
