## Verdict: APPROVE

No blocker was found. The `unsafe`/objc2 code is sound for what it does, the latch
rules are correctly implemented and tested, the never-auto-send invariant holds on
every path including error paths, the TS/Rust seam matches field-for-field, file
errors are surfaced, and every verifiable claim in the three worker reports is
substantiated in the diff. Three MAJOR follow-ups below should be tracked (one is
already in `backlog.md` as P2); none of them justifies holding the merge.

## Findings

### MAJOR-1 — VoiceOver letter chords are invisible to the latch (`gesture.rs`, `hotkey_flags.rs`)

- **Where:** `app/src-tauri/src/gesture.rs:60-78` (`ModifierSample` has only
  `control/option/command/shift`); samples originate in
  `app/src-tauri/src/hotkey_flags.rs:150-162` (`flagsChanged` only).
- **Failure scenario:** a VoiceOver user (whose default modifier is exactly
  Control+Option) holds the pair and presses a *letter* key to navigate.
  Letters produce `keyDown`, not `flagsChanged`, so the latch sees a clean,
  unblocked pair hold lasting well over 300 ms and starts recording. Every
  VoiceOver navigation session becomes an unintended microphone recording.
  The Command/Shift poison (`gesture.rs:103-122`) only covers chords that
  include Command or Shift — the most common VoiceOver chords (VO + letters)
  pass straight through the 300 ms gate.
- **Blast radius is bounded:** release never sends (see invariant note below);
  the worst case is stray local WAVs, not exfiltration. The worker report
  (`backlog/2026-09-19-modifier-only-and-horizontal-expand.md`, "honest
  limitations") discloses exactly this limit, and the `Control+Option+Space`
  fallback plus the planned on/off toggle are the right mitigations.
- **Recommendation:** keep the P2 toggle item already in `backlog.md`; consider
  adding a key-down tap (any `keyDown` while a pair hold is pending cancels the
  arm) when a settings surface exists. Not merge-blocking.

### MAJOR-2 — A wedged audio driver strands `Capture` in `recording` forever (`capture.rs`)

- **Where:** `app/src-tauri/src/capture.rs:95-125` (`stop` breaks out of the
  condvar wait after `STOP_TIMEOUT` but leaves `Inner::Recording` in place).
- **Failure scenario:** if the capture worker never finishes (wedged driver,
  hung `stop.recv` consumer, or a worker panic — the report itself notes there
  is no `catch_unwind`), `stop()` returns a `recording` snapshot while the
  engine stays `Recording`. The latch has already cleared `active`, so the next
  gesture emits `Start` → `capture.start` sees `Recording` → returns early as
  "idempotent" without spawning a worker. The overlay is now stuck showing
  recording with no live stream, and only a restart heals it. The 1 s watchdog
  heals the *latch*, never the *engine*.
- **Recommendation (A1 hardening, not this PR):** on `STOP_TIMEOUT` expiry,
  transition to `Inner::Error("audio driver did not respond")` (or drop the
  stale `Active` and allow a fresh `start`), and/or wrap the worker body in
  `catch_unwind`. Normal finalization is milliseconds, so the timeout path is
  genuinely exceptional — failing loudly there is strictly better than a silent
  stuck state.
- **Related and confirmed:** a worker panic has the same effect (state stays
  `recording`). The a0 report discloses this ("no catch-unwind ... noted as a
  hardening item") — substantiated, still open.

### MAJOR-3 — WAVs accumulate with no retention policy (`capture.rs`, `lib.rs`)

- **Where:** `app/src-tauri/src/capture.rs:126-138` (`next_path`), recordings
  dir created in `app/src-tauri/src/lib.rs` under `app_data_dir/recordings/`.
- **Failure scenario:** every hold-release cycle writes one permanent WAV
  (device rate, e.g. 48 kHz stereo 16-bit ≈ 190 KB/s; long sessions are MBs).
  Releasing over `ready` state or retrying after an error orphans the previous
  file — nothing ever deletes, rotates, or caps the directory. A heavy user
  combining this with MAJOR-1's stray VoiceOver recordings grows
  `~/Library/Application Support/` without bound.
- **What is good:** error paths remove the truncated file
  (`capture.rs:192-196`), the directory is outside the repo, and write/dir/
  finalize failures all surface as `Inner::Error` → overlay error row. No
  silent swallowing.
- **Recommendation:** A1 (which consumes the WAV for STT) should own the
  lifecycle: delete-on-transcribe or a size/age cap. File as a P1/P2 backlog
  item.

### MINOR-1 — `capture.start` can swallow a restart racing finalization (`capture.rs:71-94`)

- **Where:** `start` early-returns while `Inner::Recording`, even if a `stop`
  was already requested and the worker is milliseconds from `Ready`.
- **Failure scenario:** requires `capture_start` → `capture_stop` →
  `capture_start` within the finalization window. The second start is dropped
  (no new worker, first path wins). **Currently unreachable from the shipped
  UI** — verified by grep that `App.tsx` never invokes `capture_start` /
  `capture_stop`; only the hotkey driver (which is transition-driven and cannot
  produce this interleaving) and hypothetical devtools callers do. Downgraded
  to MINOR for that reason; worth a generation counter if the UI ever gains
  record buttons.

### MINOR-2 — `apply` uses panicking `app.state::<Capture>()` (`hotkey.rs:216-237`)

- Setup order (`lib.rs`: `manage(Capture)` before `hotkey::setup`, driver
  spawned last) makes this safe today, and `handle_shortcut` already uses the
  non-panicking `try_state`. For symmetry and to survive any future setup
  reorder, `apply` should use `try_state` + early return like its sibling.
  One-line hardening; not blocking.

### MINOR-3 — Repeated Accessibility prompt while untrusted (`hotkey.rs:58-66`)

- `prompt_for_trust()` fires on *every* launch until trust is granted. macOS
  normally shows the consent dialog once per binary signature, so this is
  likely benign, but if the OS re-presents per call it becomes a nag screen.
  Consider prompting once per install (persist a flag) or only after the user
  first attempts the gesture. Observational; not blocking.

### NIT-1 — `Retained::into_raw` is never balanced (`hotkey_flags.rs:163-168`, `remove`)

- `remove` calls `removeMonitor` but never reconstructs the `Retained` (no
  `Retained::from_raw`), so the two monitor objects leak — deliberately, since
  `teardown` runs only on `RunEvent::Exit` as the process goes away. Sound,
  correctly documented, zero runtime effect. Recording it only so a future
  reader does not "fix" the leak into a use-after-remove.

### NIT-2 — Teardown coverage is exit-only (`lib.rs`, `hotkey.rs:141-152`)

- Monitors unregister solely on `RunEvent::Exit`. Abrupt termination (kill,
  crash) skips it — harmless, because the subscriptions die with the process.
  No action needed; noted for completeness.

### NIT-3 — TS fallback radii differ from the Rust fallback (`App.tsx:12-21` vs `notch.rs`)

- `FALLBACK_GEOMETRY` hardcodes `pillTopRadius: 4, pillBottomRadius: 9,
  shellEarRadius: 6, shellBottomRadius: 14`, while Rust `FALLBACK` derives
  `radii_for(34, 66)` = `4.25 / 8.5 / 5.94 / 13.86`. First-paint-only
  discrepancy (the 2 s `notch_geometry` poll overwrites it immediately);
  sub-point visually. Suggest deriving the TS fallback from the same formula
  or adding a comment that it is approximate.

### NIT-4 — `isPolarisEvent` admits malformed payloads; `describeEvent` has no default (`interfaces/src/index.ts`, `polaris.ts`)

- The tag-agnostic guard (deliberate, documented) lets `{type: "capture_status"}`
  without `status` reach `App.tsx`'s handler, where `setStatus(event.status)`
  would store `undefined`. Traced the render: `status.recording?.` is
  optional-chained and an undefined `state` falls through to the "Connecting"
  label — no crash, just a misleading paint. Since Rust always emits complete
  shapes (pinned by JSON tests), this is defense-in-depth only.

### NIT-5 — Cross-restart filename collision is theoretically possible (`capture.rs:126-138`)

- `polaris-{millis}-{sequence}` restarts `sequence` at 0 per launch; two
  launches capturing within the same millisecond would collide and `hound`
  would truncate. Requires same-millisecond double-launch — not worth fixing,
  noted only.

## Point-by-point against the review brief

1. **`unsafe` / objc2 (`hotkey_flags.rs`, `notch.rs`).** Every `SAFETY:` comment
   checked out: the `NSEvent` borrow is confined to the callback duration; the
   local monitor returns the incoming pointer unchanged (the documented
   pass-through contract); `AXIsProcessTrusted*` calls have no preconditions;
   the `Send`/`Sync` impl on `FlagsMonitor` is justified because the raw
   pointers are only dereferenced in main-thread `remove`. The
   `into_raw`-leak-then-`removeMonitor` pattern keeps the subscription alive
   and unregisters exactly once via `guard.take()`; double-remove is
   impossible. The monitor token cannot be dropped early — both tokens live in
   `HotkeyRuntime` (a Tauri managed state, app lifetime), and the `RcBlock`s
   are correctly dropped after registration because AppKit copies monitor
   blocks. AppKit registration happens in `setup` (main thread — the same
   assumption `notch.rs` already relies on); removal happens on
   `RunEvent::Exit` (main thread). The one genuine deviation — polling
   `NSEvent::modifierFlags_class()` on the driver thread — is disclosed in the
   worker report and is covered by objc2-app-kit 0.3 marking `NSEvent`
   any-thread; `+[NSEvent modifierFlags]` is conventionally thread-safe.
2. **Gesture latch.** Cannot get stuck *in the latch*: every `active` transition
   is paired, trigger ownership is clean (a shortcut release never stops a
   modifier capture and vice versa), poison requires full release, and the
   watchdog replays ground-truth disagreements through the normal transition
   path, healing both missed releases and missed presses (both covered by
   tests). The 300 ms delay + Command/Shift poison defeats chord
   *fragments* and short taps, but **not** VoiceOver letter chords
   (MAJOR-1) — a sensor limit of `flagsChanged`, not a logic bug. No races
   between the three drivers: all inputs serialize through one `mpsc` channel
   into a single-threaded driver loop, and `capture.start` idempotency absorbs
   duplicate Starts.
3. **Capture concurrency.** No lock is held across a blocking operation
   (`start` drops the guard before spawning; `stop` waits on a condvar, which
   is the intended blocking primitive); every lock uses
   `unwrap_or_else(into_inner)`, so a poisoned mutex degrades instead of
   panicking. The audio callback locks briefly per chunk. Remaining holes are
   MAJOR-2 (timeout/panic strands `recording`) and MINOR-1 (raced restart).
4. **Never auto-send.** Proven by construction: `grep` for
   `sendPayment|submit|transmit|dispatch` in `src-tauri/src` finds only
   comments and the pre-existing (never-emitted-in-A0) `TxSubmitted` variant.
   `Action::Stop` → `capture.stop()` finalizes a WAV and emits `ready`; the UI
   (`App.tsx`) invokes no commands at all — it is listen-only — and the 6 s
   `ready` dwell is presentation-only. "Ready to send" is label copy. Holds on
   all error paths (errors land in `Inner::Error`, never in a send path —
   there is no send path).
5. **The seam.** Verified identical: `CaptureState` (`snake_case` ↔
   `"idle"|"recording"|"ready"|"error"`); `CaptureRecording.path` /
   `durationMs` (`camelCase`); `CaptureStatus.{state,recording,error}` with
   explicit `null`s (Rust has no `skip_serializing_if`, `#[serde(default)]`
   tolerates absence); `PolarisEvent` externally tagged
   (`tag="type"`, `snake_case` + `camelCase` fields) with `hotkey_permission`
   / `capture_status` (`status` object) / `audio_captured`
   (`path` + `durationMs`) matching the TS union member-for-member; JSON-shape
   tests pin all of it on the Rust side. `NotchGeometry` carries the same 8
   `camelCase` fields both sides (modulo NIT-3's fallback constants).
   `HotkeyState` (`snake_case` ↔ `"down"|"up"`) matches.
6. **Resources.** WAVs go to `app_data_dir/recordings/` (outside the repo);
   growth is unbounded (MAJOR-3). Errors surface as `Error` state + overlay
   row + `eprintln`; truncated files are removed. Nothing is swallowed.
7. **Honesty check.** All three reports substantiated:
   - `2026-09-19-a0-push-to-talk-notch.md`: `dev_self_test` is indeed deleted;
     seam/state-machine/overlay claims match the diff (stale 199×36 numbers
     are its own pre-fix measurement, corrected by the next report — a
     consistent narrative, not a contradiction). The `catch_unwind` caveat is
     real (MAJOR-2).
   - `2026-09-19-notch-shape-fix.md`: `idle_cutout_size` returns the exact
     cutout, the radii table matches `radii_for`, the CSS `@property --ear`
     registration and the zero-ear-at-rest claim verified in `index.css`;
     limitations section is candid.
   - `2026-09-19-modifier-only-and-horizontal-expand.md`: "11 unit tests" =
     9 latch + 1 shortcut + 1 permission-wire test — counted, correct. Token
     lifetime, trust-gating (driver gates on `AXIsProcessTrusted`, install
     still attempted with a graceful `None` log), 1 s watchdog, poison rule,
     and the height-transition removal (`index.css:106-109` transitions only
     `width, border-radius, --ear`) all verified verbatim in the diff. Open
     items (sleep/lock force-stop, VO toggle) are honestly listed as
     unimplemented and the toggle is already a P2 backlog row.
