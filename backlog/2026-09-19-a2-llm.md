# Report: A2 — LLM roundtrip (transcript → intent)

- **Date:** 2026-09-19
- **Worker/Agent:** opencode worker (deepseek-v4.1-flash)
- **Branch/Worktree:** `feat/a2-llm` / `.worktrees/a2` (based on `feat/a1-ondevice-stt`)
- **PR:** none (task: push only, no PR, no merge, no tag)

## Objective

Turn the A1 transcript into a structured, validated **intent** (a tool call with
arguments) with a real LLM, behind a swappable provider port, surfaced in the UI,
without executing anything on-chain.

## Completed

1. **Real OpenAI-compatible client behind the existing port.**
   `agent/src/llm/openai.ts` implements the `AgentLlm` port from `loop.ts`:
   `POST {baseUrl}/chat/completions` with `tools` / `tool_choice: "auto"`, parsing
   `choices[0].message.tool_calls`. It always sends a stable
   `x-opencode-session: ses_<32 hex>` per client instance and an optional
   descriptive `User-Agent`. `fetch` is injectable, so the exact request shape is
   unit-tested with no network.
2. **Provider is swappable by config.** `POLARIS_AGENT_BASE_URL`,
   `POLARIS_AGENT_MODEL`, `OPENCODE_API_KEY` are the only provider inputs
   (`agent/src/llm/config.ts`). OpenCode Zen Go → Groq/OpenRouter is a `.env`
   change. A non-http(s) base URL is rejected as a `config` error, not a failed
   request later.
3. **`send_payment` tool + intent validation.** `agent/src/tools/payment.ts`
   defines the schema `{ amount, asset, recipient, memo? }`, requires approval,
   and exposes `toIntent()`. It validates locally and returns the shared
   `Intent`: `{ kind: "send", asset, amount, recipient, source }` — a decimal
   **string** amount, asset defaulting to `USDC`, recipient kept verbatim (an
   address-book alias such as "Ahmet" is valid). **Nothing executes on-chain.**
4. **Loop handles the three outcomes correctly.**
   - Approval-gated tool call → validated into an `Intent` and returned; the loop
     emits `agent_status: awaiting_approval` and never calls `run()`.
   - Bad model arguments → an `input` `AgentError` is converted into a
     clarification, not a bogus intent.
   - No tool call / more than one action → a clarification.
   - Non-approval tool (`noop`) still runs, preserving the round-trip proof.
5. **Errors split like A1.** `agent/src/errors.ts` gives every failure a short,
   UI-safe `label` ("Net error", "Agent auth", "Bad response", …) and a full
   `detail`. The webview shows the label and logs the detail to the console; the
   CLI prints both.
6. **UI wiring.** `app/src/lib/agent.ts` consumes the Rust `transcript` event via
   `App.tsx`, runs the same agent core, and surfaces the result in
   `app/src/components/AgentTrace.tsx` below the notch (transcript + intent or
   answer, with the latency). `intent in <ms> ms` is logged to the console.
7. **Secret never enters the webview.** The provider sends **no CORS headers**
   (verified: an `OPTIONS` preflight returns 404 with no
   `Access-Control-Allow-*`), and the webview must not hold the credential, so the
   webview calls a same-origin `/agent-api` path. The Vite dev server proxies it
   to `POLARIS_AGENT_BASE_URL` and injects `Authorization` + `User-Agent`
   server-side (`app/vite.config.ts`). Confirmed with `grep` that the built bundle
   contains neither the key nor the provider URL.
8. **Manual CLI entry point.** `npm run cli -w @polaris/agent -- "<text>"` is the
   "enter" half of "speak/enter": it loads the root `.env`, runs one turn, and
   prints the JSON result on stdout and the events/latency on stderr.
9. **Tests (28, no network).** `agent/src/tools/payment.test.ts`,
   `agent/src/loop.test.ts`, `agent/src/llm/openai.test.ts`,
   `agent/src/llm/config.test.ts` use a `ScriptedLlm`/`MockLlm` and a capturing
   `fetch` stub.

## Unverified (stated plainly)

- **The full in-app path was not run.** Rust transcript → `App.tsx` → agent →
  `AgentTrace` needs a real microphone and the Speech permission, i.e. a human.
  Its two halves were verified independently (proxy via curl; agent via CLI and
  28 unit tests), but the joined path is not observed.
- **Built/packaged app does not reach the LLM.** `/agent-api` exists only in the
  Vite dev server. `npm run build` is green, but a packaged Polaris would show
  "Net error" until the proxy moves into Rust (see Handed off). This is the
  intended A2 scope (dev demo), not an oversight.
- **Latency is single-sample** per command (2.1–4.2 s on this machine), not a
  distribution.
- **`node:test` type support** comes from the hoisted `@types/node` (as with the
  existing keeper suite); it is not declared in `agent/package.json`.

- None for A2. The provider answered correctly on the first real call once the

## Review Notes

- The intended seam is untouched: `interfaces/` is unchanged (no new
  `PolarisEvent` variant; the Rust mirror stays in sync). The intent travels back
  from `runTurn` in `AgentTurnResult` and is rendered from React state.
- `toIntent` was added to `AgentTool` so the loop can validate an approval-gated
  call **without** executing it — the A2 contract ("stops at a parsed intent").
- `tool_choice: "auto"` is deliberate; forcing a tool would turn "bugün hava
  nasıl" into a bogus intent.
